# VISIONCARE — PHASE 8 CHECKPOINT: GRAD-CAM VISUALIZATION

## 1. Executive Summary

Phase 8 successfully implements **Grad-CAM (Gradient-weighted Class Activation Mapping)** for the trained VGG19 retinal disease screening model. The visualization capability allows clinicians, researchers, and students to inspect the exact spatial regions of a retinal fundus photograph that influenced the network's classification for any of the four target eye health categories (Cataract, Diabetic Retinopathy, Glaucoma, and Normal).

All implementations preserve the strict project requirements:
- Website and project name strictly maintained as **VisionCare**.
- **Zero occurrences of the word "AI"** anywhere in the visible user interface, headings, descriptions, code comments, or API responses.
- Heatmaps are derived directly from actual model gradients computed via `tf.GradientTape()` on convolutional layer `block5_conv4`. No simulated or decorative heatmaps.
- Model weights were preserved and not modified or retrained.
- In-memory model caching was strictly enforced (zero disk reloading per request).
- The primary screening classification is preserved even if visualization encounters a failure.
- Screen history, PDF report generation, and cloud deployment were kept out of scope for Phase 8.

## 2. Architecture & Target Layer Analysis

### Layer Selection: `block5_conv4`
The trained model (`backend/models/eye_disease_model.keras`) is a Functional Keras model built on the VGG19 backbone. Inspection of layer structure confirmed:
- **Layer 20:** `block5_conv4` (`Conv2D`)
  - Activation: ReLU
  - Output Tensor Shape: `(None, 14, 14, 512)`
- **Layer 21:** `block5_pool` (`MaxPooling2D`, shape `(None, 7, 7, 512)`)
- **Layer 22:** `gap` (`GlobalAveragePooling2D`, shape `(None, 512)`)
- **Layer 23:** `dense_256` (`Dense`, shape `(None, 256)`)
- **Layer 24:** `dropout_0.5` (`Dropout`, rate 0.5)
- **Layer 25:** `predictions` (`Dense`, 4 units, Softmax activation)

`block5_conv4` is the final convolutional layer of the network before spatial pooling. It preserves high-level spatial semantics and anatomical features (such as the optic disc, vascular architecture, optic cup, and macular regions) while retaining spatial coordinates $(14 \times 14)$.

## 3. Grad-CAM Mathematical Formulation & Service Implementation

The Grad-CAM calculation was encapsulated in `backend/app/services/gradcam_service.py` (`GradCAMService`):

1. **Sub-Model Construction:**
   Constructs a gradient sub-model reusing the in-memory model loaded by `ModelService`:
   ```python
   self._grad_model = tf.keras.models.Model(
       inputs=current_model.inputs,
       outputs=[target_layer.output, current_model.output]
   )
   ```
2. **Gradient Computation:**
   Under a `tf.GradientTape()`, the preprocessed RGB tensor is passed through the sub-model:
   ```python
   with tf.GradientTape() as tape:
       conv_outputs, predictions = grad_model([preprocessed])
       target_score = predictions[:, target_idx]
   grads = tape.gradient(target_score, conv_outputs)
   ```
3. **Global Average Pooling:**
   Spatial gradients are pooled across height and width to calculate channel importance weights $\alpha_k^c$:
   ```python
   pooled_grads = tf.reduce_mean(grads, axis=(0, 1, 2))
   ```
4. **Weighted Activation & Rectification (ReLU):**
   ```python
   heatmap = conv_outputs[0] @ pooled_grads[..., tf.newaxis]
   heatmap = tf.squeeze(heatmap)
   heatmap = tf.maximum(heatmap, 0.0)
   ```
5. **Safe Normalization:**
   ```python
   max_activation = tf.math.reduce_max(heatmap)
   if max_activation > 1e-10:
       heatmap = heatmap / max_activation
   else:
       heatmap = tf.zeros_like(heatmap)
   ```
6. **Bicubic Upsampling:**
   The $14 \times 14$ activation map is resampled to the exact dimensions of the uploaded photograph using PIL bicubic interpolation (`Image.Resampling.BICUBIC`).
7. **Colormapping & Blending:**
   - Single-channel normalized heatmap is mapped via `jet` colormap into an RGB representation.
   - The overlay is generated by alpha-blending $40\%$ heatmap with $60\%$ original fundus photograph:
     $$I_{\text{overlay}} = 0.4 \times I_{\text{heatmap}} + 0.6 \times I_{\text{original}}$$
   - Both the pure heatmap and blended overlay are encoded into in-memory Base64 PNG data URLs (`data:image/png;base64,...`).

## 4. API Endpoint (`POST /api/gradcam`)

Added to `backend/app/routes/prediction.py` and documented in OpenAPI schema:

- **Method:** `POST`
- **Route:** `/api/gradcam`
- **Parameters:**
  - `file`: Multipart form file upload (`UploadFile`, JPG/JPEG/PNG, max 10 MB).
  - `class_index` (optional query parameter): Integer in $[0, 3]$. If omitted, defaults to the model's top predicted class.

### Example Response Body:
```json
{
  "status": "success",
  "message": "Grad-CAM visual explanation generated successfully.",
  "prediction": "Glaucoma",
  "class_index": 2,
  "confidence": 0.971,
  "target_layer": "block5_conv4",
  "heatmap_data_url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAgAAAAIACAYAAAD0eNT6...",
  "overlay_data_url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAgAAAAIACAYAAAD0eNT6...",
  "original_dimensions": [512, 512],
  "scores": {
    "Cataract": 0.0003,
    "Diabetic Retinopathy": 0.0001,
    "Glaucoma": 0.971,
    "Normal": 0.0286
  }
}
```

### HTTP Error Codes:
- `400 Bad Request`: Invalid image format, corrupted stream, 0-byte file, oversized (> 10MB) file, or out-of-bounds `class_index`.
- `503 Service Unavailable`: Classification model weights not loaded.
- `500 Internal Server Error`: Unexpected runtime failure.

## 8. Limitations & Notes

1. **Receptive Field Resolution:** The feature maps from `block5_conv4` have an inherent spatial resolution of $14 \times 14$. While bicubic interpolation yields smooth and interpretable overlays at original image resolution, Grad-CAM highlights general anatomical regions rather than cellular-level lesion boundaries.
2. **Educational Screening Scope:** Grad-CAM visualizations represent algorithmic feature importance, not confirmed medical diagnoses or certified pathological segmentations.
3. **Model Weights Invariance:** Model weights remain strictly frozen and unaltered.
